HCI ONE Board Remote Manual

Version 2.0 · October 2026

Board Remote is a Windows tool that keeps every HCI device connected over network ADB: live screens with touch, a heartbeat with alerts, and bulk deploys of apps and room numbers. The quick start gets you running; Appendices A to I are the reference.

Quick start

Seven steps take a new PC from zip file to watched boards in about ten minutes. The PC must be on the same network as the boards, and each board needs USB debugging and network ADB on port 5555 (Appendix A).

  1. Unzip HCI ONE Board Remote.zip to a folder that will stay put, for example C:\HCI\Board Remote.
  2. Double click SETUP.bat. It downloads Node and adb into the tools folder, puts a Board Remote shortcut on the desktop, and asks whether to start with Windows. Answer Y on a PC that watches boards all day.
  3. Board Remote opens in its own window. After this, open it with the Board Remote shortcut.
  4. Add the boards: Deploy, Import room list, paste rooms and IP addresses from Excel, then add them. Find boards, USB to WiFi and Add board also work.
  5. At each board, tap Allow on "Allow USB debugging?" with Always allow from this computer ticked. This happens once per board.
  6. Deploy, Push an app, pick HCI ONE ADB, select every board, Push. Network ADB then survives reboots.
  7. Device health, the gear: site name, the Teams links for HCI Support and Hospital IT, then Send a test alert.

Appendix A. Before you install

Board Remote runs on one Windows PC and talks to each board directly over the hospital network. Nothing is installed on a server, and nothing leaves the network except the optional Teams alerts and Claude diagnosis.

The PC

  • Windows 10 or 11. No admin rights are needed.
  • On the same network as the boards, or with a route to them on TCP port 5555 (and 65037 for cameras).
  • Internet once, during SETUP, to download Node and adb. With no internet, run SETUP.bat on another PC and copy the whole folder across, tools folder included.
  • Microsoft Edge opens the dashboard as its own window. Any browser works at http://localhost:7755 on that PC, and only that PC can open it.

Each board

SettingWhy it matters
USB debugging on, in Developer optionsLets the PC connect at all
Network ADB on port 5555Lets the PC connect without a cable. USB to WiFi turns it on from a USB connection. Cameras only work on port 65037; Board Remote finds them there and never moves them to 5555.
Allow tapped once for this PC, with Always allow tickedThe board trusts this PC's key from then on
HCI ONE ADB keeper installedKeeps network ADB on after a reboot. Some boards also need root or the factory setting.
A DHCP reservationThe board keeps its IP, so the Boards list stays right
Unit, closet and room filled inDevice health groups boards by closet and spots a closet outage

Site size

One PC watches a whole site. Board Remote was load tested with 154 simulated devices (75 whiteboards, 75 door signs and 4 Unit Status Boards):

WhatHow it scales
HeartbeatEach board about every 27 s, spread evenly: about 6 small text checks a second for 150 boards, never more than 16 at once
ScreensOnly screens in view refresh: about 3 a second on Normal and 8 on Live, whatever the site size. Off costs nothing.
ReconnectsAt most 16 at once. A board that has not answered for 2 minutes is tried every 30 s, and Connect all tries at once.

The PCBoard Remote itself used about 70 MB of memory and a few percent of one core. Any current office PC is enough.

What Hospital IT sets up once

  • A DHCP reservation for each board, so a board never moves to a new address.
  • Ports 5555 and 65037 (cameras) open from the Board Remote PC to the device network. Nothing else needs them.
  • A time server the boards can reach (NTP, UDP 123). Without it clocks drift and sign ins fail.

Appendix B. Install, upgrade and remove

SETUP.bat runs once. After that Board Remote runs quietly in the background, and the window is only a view of it: closing the window does not stop the watching or the alerts.

What SETUP.bat does

  1. Uses the Node already on the PC (version 16 or newer), or downloads a portable copy into the tools folder.
  2. Downloads scrcpy, which brings adb, into the tools folder. If Android Studio is on the PC, Board Remote uses its adb so the two never fight.
  3. Puts a Board Remote shortcut on the desktop.
  4. Asks "Keep your boards connected every time Windows starts?" Y starts Board Remote quietly at every sign in; N turns that off.
  5. Opens Board Remote.

The three files you use

FileWhat it does
START.bat, or the desktop shortcutStarts Board Remote if it is not running, then opens the window. The very first run calls SETUP.bat.
STOP.batStops Board Remote. Boards keep working; they are just not watched. Stop Board Remote at the bottom of the Boards page does the same.
SETUP.batRun again any time to repair the tools folder or change the start with Windows answer.

Upgrade

  1. Run STOP.bat.
  2. Unzip the new version over the same folder and replace the files.
  3. Run START.bat. Boards, settings, history and the app library stay, because they live in files the zip does not contain (Appendix I).

Move to another PC. Copy the whole folder, then run SETUP.bat on the new PC. Each board asks for Allow once more, because every PC has its own ADB key.

Remove. Run STOP.bat. Press Windows and R, type shell:startup, and delete Board Remote there. Delete the desktop shortcut and the folder.

Snapshots on the top bar saves a picture of every connected board's screen to a folder, so you can line up what was on a board against the messages that came in. Files are named by room, board and time, under the folder shown (by default a snapshots folder next to Board Remote, which you can change). The gallery shows the newest first; click one to open it full size, or Open folder to see them all. A snapshot is a picture of the board's screen, so keep the folder inside the hospital.

Appendix D. Device health

Device health checks every board every 30 seconds, says where a problem sits and who owns it, and fixes the common ones remotely. Pick a board on the heartbeat wall to see its detail in the middle column.

Heartbeat states

StateMeaning
OnlineAnswered its last heartbeat
LateNo answer for 45 s
DegradedAnswers, but something is wrong: clock, app, crash, screen, storage, server, or Allow pending
OfflineMissed heartbeats for 90 s (changeable in Settings)
Checking or pausedNot checked yet, or you disconnected it

The wall groups boards by unit, closet and room, one square per board. When 3 or more boards in one closet (or one network, if no closet is set) go quiet within 2 minutes, it is one problem: Device health raises a single closet alert for Hospital IT instead of one per board. That alert stays open until every board in it is back, so after a power or switch outage the boards that boot last do not each raise an alert of their own.

The fix the first read recommends is highlighted. Each fix asks to confirm, shows the commands it ran, then checks the board again and says whether it worked. Open live view jumps to the board in Boards.

Diagnose with Claude (optional, needs an API key in Settings) sends the board's facts and check results, gets back a cause, an owner, steps and a draft alert, and takes follow up questions. Screenshots are never sent, and log lines only if Settings allows it. Without a key, Copy evidence for Claude copies the same facts to paste into Claude.

Who gets told lists each alert with its delivery (sent, failed, shown). Mark acknowledged stops the escalation. The right column holds open issues, the event feed and the alert rules in force.

Edit (beside the board's name) sets its name, type, unit, closet, room and the app to watch. Use the app on screen now fills in the app that is in front.

Log history, camera and LED ring

A board keeps only a small log of its own, so Board Remote pulls each connected board's log to this PC about every minute and keeps the last 48 hours (change this in Settings). In the console, Log history shows it with a time range (1, 6, 24 or 48 hours), a level filter (all, warning and up, or errors) and search. Camera and LED ring are the same log filtered to the lines those parts of the board write; tune which words they match in Settings. Crash reads the board's crash log live. Pull now grabs the latest at once. Recent logs still pulls the last 200 lines live, and is the only log Claude is ever sent, and only if Settings allows it. Save snapshot saves this board's screen to the Snapshots folder.

LED bezel control (door signs)

When the board you have open is a door sign, the console shows LED bezel. Pick Solid or Flash, then a colour (Off, White, Red, Amber, Green or Blue), and Board Remote sends that to the sign. It uses the LED command set under the gear in Settings, which is preset for the HCI ONE Room Sign app; the door sign app on the board has to support LED control for this to take effect. If a sign does not respond, check that command, or that the sign is running a version of Room Sign that drives the ring.

On the heartbeat wall, a room with more than one board shows one coloured square per board. Click the square of the device you want to open its console, rather than the room always opening the one that needs attention most.

Appendix E. New devices

New devices lists anything that could be a board but is not on the list yet, and claims it in two taps: one here, one at the board. A device drops off the list as soon as it becomes a board, whether you claim it here or just add its IP on the Boards page.

A device shows up when it:

  • answers ADB on port 5555 (or 65037 for a camera) during a network sweep (Find devices now, or every few minutes as set in Settings),
  • is plugged into this PC by USB, or
  • is already connected to adb on this PC but not on the Boards list.

HCI Support is told when a new device answers, and it waits in the list until someone claims or hides it.

Claim a device

  1. Pick it in the list. Its model, address and how it was found are shown.
  2. Choose Add as a new board and fill in name, type, room, unit, closet and the app to watch. Or choose Replace a board and pick the dead one: the new device takes its name, room and history.
  3. Press Claim and set up. Board Remote connects; a USB device is switched to network ADB first.
  4. Someone at the board checks that the key fingerprint in the board's Allow dialog matches the one shown here, ticks Always allow, and taps Allow. Board Remote waits up to 2 minutes.
  5. Board Remote reads who the board is, installs the HCI ONE ADB keeper, syncs the clock and notes the app on screen as the app to watch. It then adds the board (or swaps it in) and takes the first heartbeat.

Each step shows in the timeline as it happens. Not ours, hide it removes a device from the list; Hidden brings it back.

Room signs

Rooms in MediaCare

Each door sign and whiteboard gets its room from MediaCare, so Deploy writes the room from your list into each device's MediaCare record.

Link MediaCare once

  1. Rooms in MediaCare. On the left enter MediaCare's Kuzzle address (for example http://10.20.0.5:7512) and a login that can change device records. Add a Kong API key only if MediaCare needs one, and tick Trust its certificate for an https address with its own certificate. Save and connect.
  2. Find device records. Board Remote reads each board's MAC, serial and IP over ADB, finds the MediaCare records that carry them, and picks the room field: a link to a room record, the room number as text in MediaCare's format (for example Room {room}), or both.
  3. Check the choices under Device records, change any by hand, then Save fields.

Set the rooms

  1. Select the boards: a whole unit, or one type.
  2. Preview the changes. Each row shows the MediaCare record, its room now and the change.
  3. Test on one. Board Remote writes that record, reads it back and restarts the app. Look at that board's screen.
  4. Apply to the other devices.
  5. Undo puts back the old rooms of the last batch.

Appendix I. Security, privacy and files

Board Remote keeps its secrets in one file, boards.json, and never sends patient information anywhere.

  • Only this PC can open the dashboard (localhost:7755). Other PCs and web pages cannot reach it.
  • Each board trusts this PC only after someone at the board taps Allow and checks the key fingerprint.
  • boards.json holds the Teams links, the Claude key and the MediaCare login. Keep it private, back it up, and never email it.
  • No patient data leaves. Claude never receives screenshots, and gets log lines only when Settings allows it. In MediaCare, Board Remote reads only device and room records.
  • The keeper's signing key stays with HCI. A manufacturer gets only the signed HCI ONE ADB app.

To keep a setup, back up boards.json, deploy.json and apks\library. An upgrade never touches them.

Appendix J. Remote (proof of concept)

HCI ONE Remote lets HCI support see and fix this site's boards from a phone or PC anywhere, the way TeamViewer reaches PCs. This PC dials out to an HCI relay; nothing at the hospital is opened to the internet. This version is a proof of concept for demo boards only.

Set it up

  1. Click Remote at the bottom of the Boards page.
  2. Enter the relay address HCI gives you, enter the one time code from HCI, then Connect this site. The code works once, within 24 hours.

Connecting is the consent. The hospital gives HCI permission for ongoing remote support in the install agreement, and connecting the site with HCI's code is that permission in action. From then on HCI has the access below on every board, nobody here is asked again, and Remote stays on, also after a restart, until HCI disconnects the site. A Remote tab then stays in the navigation on every page.

AccessWhat HCI can do
HealthBoard status, heartbeat and open issues
FixesRestart app, Reboot and Wake screen
Live viewThe board's live screen with touch, Back and Home

The hospital always sees HCI's access. While HCI is viewing a board, a bar at the top of every Board Remote page says who and which board, with End, so anyone here can stop a session. The Remote page lists every action under Activity. To move a site to another relay, HCI removes it in the viewer's Admin and makes a new code.

Nothing shows on the boards. These signs of remote access appear only here, on the Board Remote PC. No notice of remote access ever appears on a whiteboard or door sign. Whether and how patients are told about in room devices stays hospital policy, the same as for any other monitoring.

The relay is a separate HCI server, where HCI signs in to its web viewer from any phone or PC. Board Remote reaches it over https (port 443) only. A copy is in the relay folder for testing on one PC: RELAY.bat starts it on port 8780. See relay\README.txt.

Before real patient sites: Microsoft single sign on with multifactor, video encrypted end to end, access by role per site, and a security review.

Appendix K. Morning audit

The Audit view gives hard evidence of what was on each room screen, so a report that an infotile "fell off" can be checked against the record instead of a memory. It does three things.

  • Overnight record. Every minute each board with a room is checked. A board counts as down once Device health misses its heartbeat, dated from its last heartbeat, so the report shows exactly when it dropped and when it came back. If Board Remote itself was not running, the report says so, rather than claiming a board was up when nobody was watching.
  • Morning run. Every morning at the set time (6:30 by default), and whenever you press Run audit now, each audited board gets a snapshot and Board Remote reads the words on its screen. It keeps only whether a fall risk or contact tile was showing. The words themselves, which can include patient names, are never saved. If this PC was off at the set time, the audit runs when it comes back, up to three hours late.
  • The hospital's list. Each morning the hospital sends the rooms that should show fall risk and the rooms that should show contact, room numbers only. Paste it, choose the file, or drop it into the audit\inbox folder. Any of these work: a table with Room, Fall risk and Contact columns; lines like "Fall risk: 401, 405"; or a heading followed by one room per line. Dates and times on the list are ignored.

The report then compares the list with the screens, room by room. Missing on screen means the list says the tile should be there and no board in the room showed it. On screen, not on the list means a tile showed that the list does not call for. Could not check means the board was not connected or its screen text could not be read; open the room to see its snapshot. Click a room for its snapshot, the tiles that were read and its overnight drops. Report CSV saves the day as a spreadsheet, and History keeps every day for 90 days. With a Teams link set under Device health, a short summary with room numbers goes to HCI Support after each run, and again when the list arrives later.

A tile counts only when a piece of text on the screen is exactly one of the tile words in Settings, so "Contact your nurse" never counts as a contact tile. If a hospital's tiles use other words, add them there. Which board types are audited (whiteboards and door signs by default) is set there too.

Appendix L. HCI ONE Cloud

HCI ONE Cloud puts every Board Remote PC at a hospital into one web dashboard, so several techs can work the same hospital and hospital IT can see and fix boards from a browser. Joining is optional. Board Remote works the same without it.

  • Join. In the web dashboard, go to PCs, Make a code. On this PC open Remote, and under HCI ONE Cloud enter the code (the address is already filled in: https://remote.hci-tv.com). A code works once and lasts 24 hours.
  • One board, many PCs. Boards are matched by MAC address or serial, so a board two PCs can reach shows once. Commands go through the PC that heard from it most recently. If that PC goes off, the next one takes over.
  • Rooms sync both ways. A room, unit or closet changed here shows in the web dashboard and on the other PCs within seconds, and the reverse. The most recent change wins, field by field.
  • The HCI lock. Once HCI locks a board's location, its room, unit and closet cannot be changed here or in the web dashboard. Edit shows "HCI locked the room, unit and closet". The name, address and app can still be changed.
  • What leaves this PC. The board list (identity, room, unit, closet, type, model) and health (state, headline, last heartbeat). Never screens, snapshots, screen text or device logs.
  • Commands from the web. Only the fixed list: restart app, reboot, wake, fix clock, free storage, reconnect ADB, install the keeper, door sign light, health check and the morning audit. They run through this PC's own Board Remote exactly as if clicked here, and each one is logged in both places.
  • Leave. Leave the cloud on the Remote view, then remove the PC under PCs in the web dashboard.

The connection goes out from this PC on port 443 only. Nothing is opened to the internet.

Appendix M. Windows app and updates

From 2.1, Board Remote installs with HCI-ONE-Board-Remote-Setup.exe and runs as a Windows service. It starts with Windows (no one has to sign in), restarts itself if it stops, and installs new versions from HCI ONE Cloud. Open it with the Board Remote icon on the desktop or in the Start menu.

  • Moving from a folder install. Run the installer on that PC. It stops the old Board Remote, removes its start with Windows shortcut, and brings over the boards, settings, cloud link, health and push history, app library, audit records and snapshots. The old folder is left as it was; delete it once the new one looks right.
  • Where things are. The program is in C:\Program Files\HCI ONE\Board Remote. Your boards and everything Board Remote records are in C:\ProgramData\HCI ONE\Board Remote, readable only by Windows administrators and the service, because that is where the MediaCare login and the cloud link are kept.
  • Updates. A PC joined to HCI ONE Cloud checks for a new version every 15 minutes. If its hospital is on automatic, it installs between 2 and 5 am; if the hospital approves updates, it waits until someone clicks Approve on the PCs page. Install now there skips the wait.
  • Safety. Every version is signed by HCI, and this PC checks that signature itself before installing. The new version is installed beside the running one; if it does not start and answer within two minutes, the PC goes straight back to the version it had and reports it, and does not try that version again unless someone approves it.
  • Mirror and Shell. A service has no desktop of its own, so the separate scrcpy mirror window and the adb shell window cannot open from it. Click a board for Live view with touch instead; Shell shows the command to paste into a Command Prompt.
